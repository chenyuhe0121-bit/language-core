# 01 · 技术栈与核心决策

## 决策一览

| # | 决策 | 结论 | 何时重估 |
|---|---|---|---|
| D1 | 形态 | 独立服务，不并入 FLP，不并入前端原型 | 视频链路联调时（只接接口） |
| D2 | 语言 | Python 3.9+ | 不预期改变 |
| D3 | 依赖 | 内核零第三方依赖，HTTP 层可替换 | 需要流式或高并发时 |
| D4 | 存储 | 单文件 SQLite，SQL 全部收敛在一个模块 | 并发写入成为瓶颈 |
| D5 | 检索 | 第一期关键词加规则触发，第二期再加向量 | 记忆量超 5000 条或召回不达标 |
| D6 | 模型接入 | 自写薄适配层，不用 LangChain | 不预期改变 |
| D7 | 输出协议 | 自定义双轨，不直接输出 SSML | 不预期改变 |
| D8 | 异步 | 记忆写入走后台线程，不阻塞回复 | 上生产换任务队列 |

## D1 独立成服务

它的输出是契约，必须先冻结才能让下游并行开发。它能脱离视频独立验收。它最影响留存，需要快速迭代，不能等别人的发布节奏。

与现有资产的关系：FLP 是下游消费者，companion-prototype 是将来接入时的宿主，聊天提示词目录与本项目无关。

## D2 为什么是 Python

团队既有资产是 Python，数字人推理侧几乎必然是 Python，同栈便于将来合并部署。前端由 companion-prototype 承担，本项目只出最简调试界面。

## D3 内核零依赖

segment、compiler、memory、llm 全部纯标准库，模型调用用 urllib 就够。只有 server.py 可以替换。

理由是可跑性优先：本机沙箱会拦 pip 的安装写盘，零依赖保证任何装了 Python 的机器上直接能跑。协议、编译器、记忆本来就是纯逻辑，应该是可单测的纯函数。

代价是无异步无流式，用后台线程顶住。需要 SSE 时只替换 server.py，内核不动。这是预留的升级路径。

## D4 第一期用 SQLite

单人开发阶段，PostgreSQL 需要安装配置备份，Redis 多一个进程要管，向量库在记忆只有几百条时是过度设计。

量级估算：一个活跃用户每天入库 5 到 10 条记忆，一千用户跑一年是百万级，SQLite 毫无压力。

升级路径：记忆量超 5000 条且关键词召回不达标就加向量检索；并发写入冲突就换 PostgreSQL，只改 memory.py 的连接层。所有 SQL 收敛在 memory.py 内，是这个决策能成立的前提。

## D5 第一期不上向量检索

Embedding 解决的是"换个说法也能找到"。第一期记忆少且我们主动维护结构化标签（类型、场景、时间、实体），关键词命中率已经够。

向量检索会引入新的失败模式：阈值定高了召不回，定低了污染上下文，而且失败是静默的。在还没建立记忆测试集之前引入，等于把不可观测的复杂度放进系统。顺序必须先建测试集再加向量。

## D6 不用编排框架

只写一层 call_llm(messages, params) 的薄适配。

我们需要对提示词组装有完全控制权，token 预算、注入顺序、前缀缓存命中都是成本与稳定性的核心，框架抽象会挡住。双轨输出的解析与纠错策略是产品决策，不能交给通用解析器。排查问题时必须能打印当次真实发出的完整提示词，多层抽象会让这件事变难。

代价是自己实现重试、超时、多引擎切换、参数映射，这些都是几十行代码。

## D7 自定义双轨，不输出 SSML

SSML 是语音合成层的格式，表达的是声学参数（停 200ms、这个字重读）。我们要表达的是表演意图（她有点心虚想岔开话题）。让语言模型直接产声学参数，既超出它的能力，也锁死了换 TTS 的自由。

而且我们要同时驱动语音和形象，SSML 只管前者。中间需要一个中立法，就是我们的协议，由下游适配器翻译成各家格式。

边界：语义层归本项目（分段类型、情绪标签与强度、语速档位、停顿意图、表情标签）；声学层归下游 TTS；视觉层归下游形象驱动。

## D8 异步策略

回复路径同步，记忆抽取异步。抽取本身就是一次模型调用，同步做意味着用户每说一句多等一到两秒。

代价是进程崩溃可能丢最后几条记忆，第一期接受。并发写 SQLite 用单写入线程串行化。

## 仓库结构

```
language-core/
├─ docs/                  规格文档
├─ language_core/
│   ├─ segment.py         协议解析与校验
│   ├─ compiler.py        上下文编译器
│   ├─ memory.py          记忆系统（唯一写 SQL 的地方）
│   ├─ llm.py             模型适配层
│   ├─ persona.py         角色/场景资产加载与正交校验
│   ├─ server.py          HTTP 服务（唯一可替换层）
│   ├─ assets/            角色卡、场景卡等
│   └─ web/               调试界面
├─ tests/                 回归测试集
└─ data/                  运行期数据，不进版本库
```
