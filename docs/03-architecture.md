# 03 · 总体架构

## 一轮对话的八个环节

```
用户说话
 ① 分流   判断这句话是什么，决定走哪条策略
 ② 召回   找她该想起什么
 ③ 取场景卡   她此刻在哪、什么氛围
 ④ 取关系状态 她现在对用户多熟
 ⑤ 编译   拼成她眼前的世界（compiler）
 ⑥ 生成   台词 + 旁白
 ⑦ 校验   不合格就重生成（checker）
 ⑧ 写入   异步，不阻塞回复
```

代码对应：`engine.py` 编排 ①⑧，`memory.py` 负责 ②⑧，`persona.py` 提供 ③④，
`compiler.py` 负责 ⑤，`llm.py` 负责 ⑥，`checker.py` 负责 ⑦。

## 五张卡与注入顺序

| 卡 | 存哪 | 变更频率 |
|---|---|---|
| 角色卡 | `assets/character_elise.json` | 极低 |
| 场景卡 | `assets/scenes/*.json` | 低 |
| 关系状态 | 数据库（运行期自动写） | 每通对话 |
| 风格锚点 | `persona.STYLE_ANCHOR` | 极低 |
| 边界策略 | `persona.BOUNDARY_POLICY` | 低 |

注入顺序决定成本，固定前缀放最前才能吃到前缀缓存：

```
[固定] 角色卡 + 风格锚点 + 边界策略
[随阶段变] 关系状态
[随场景变] 场景卡
[不裁剪] 输出格式规则
[每轮变] 召回记忆 + 未闭合话题 + 最近对话
[最高优先级] 危机指令（放最前，永不裁剪）
```

三条硬规则：

1. 输出格式规则不参与预算裁剪。砍掉它等于整轮报废。
2. 危机指令不参与预算裁剪。它是安全指令，优先级高于人格与剧情。
3. 未解锁的深层信息物理上不进入编译器输出。不是告诉模型别说，是让模型不知道。

## 记忆四层

| 层 | 存什么 | 存多久 | 怎么用 |
|---|---|---|---|
| 工作记忆 | 当前对话原文 | 这通对话 | 全量进上下文 |
| 短期摘要 | 最近几天的浓缩印象 | 两周 | 常驻进上下文 |
| 长期记忆 | 永久事实与经历 | 永久 | 按相关度召回 3 到 5 条 |
| 未闭合话题 | 没结的事 | 有始有终 | 按时间主动提起 |

分区维度只有一个：`character_id`。场景是记忆的标签，不是隔离墙。
回到旧场景不能失忆，也不能退回生疏。

三条流动规则：

- 工作记忆到短期摘要：每 10 条消息滚动压缩一次
- 工作记忆到长期记忆：后台异步抽取，带时间、场景、置信度
- 长期记忆到工作记忆：按相关度召回，低于阈值宁可不召回

置信度低于 0.5 的记忆直接拒收。错误记忆会自我强化，比漏记更糟。

## 校验器

模型每次输出的遵循度有方差，稳定性不能只押在提示词上。

规则型校验（免费、瞬时、100% 准）：至少一段可朗读、台词不残留格式标记、
禁用词、段数 2 到 6、台词长度、不使用 emoji、表情在场景白名单内、
情绪强度不超过当前阶段上限、台词不夹带括号描述。

其中三条是硬失败会触发重生成，其余软降级。

风格漂移用风格指纹重合度做粗粒度度量。它测的是「说话像不像这个人」的一个侧面，
不能替代人工评审，阈值需要用真实模型的输出校准。
