# 03 · 总体架构

## 一轮对话的完整链路

```
浏览器打字
  ① 收请求   server.py 定位会话，校验归属，加生成锁
  ② 抽取记忆 memory.py 从这句话里提炼事实与未闭合话题
  ③ 召回     memory.py 按相关度取回该想起的事
  ④ 编译     compiler.py 拼成她眼前的世界 + 原生多轮历史
  ⑤ 生成     llm.py 调模型，流式收字
  ⑥ 解析     segment.py 拆成台词与旁白两轨
  ⑦ 校验     checker.py 格式、长度、人格有没有跑偏
  ⑧ 落库     engine.py 存回复与反馈，后台压缩摘要
  ⑨ 推送     server.py 按段 SSE 推给前端
```

代码对应：`server.py` 负责 ①⑨，`engine.py` 编排 ②到⑧，`memory.py` 负责 ②③⑧，
`compiler.py` 负责 ④，`llm.py` 负责 ⑤，`segment.py` 负责 ⑥，`checker.py` 负责 ⑦。

**②必须赶在③之前。** 用户说「我叫阿哲」，紧接着问「你还记得我叫什么吗」，
如果抽取还在队列里没落库，她就会答「你还没告诉过我」。所以抽取是同步的，
只有写库走后台线程。

## 提示词结构

每轮由七块拼成，顺序即成本（固定前缀放最前才能吃到缓存）：

```
[最高优先级] 危机指令（命中的那一轮才有，永不裁剪）
[固定]       通用交流原则 CORE + 产品边界 BOUNDARIES
[固定]       角色设定（角色卡 JSON 原样注入，不裁剪）
[随阶段变]   双方关系
[随场景变]   当前场景（只取 context 字段）
[固定]       口吻示例 examples
[不裁剪]     输出协议规则 + 本轮说话策略
[每轮变]     召回记忆 + 未闭合话题
[原生多轮]   最近对话（以 user/assistant 消息数组形式，不是拼进 system）
```

三条硬规则：

1. **输出协议规则不参与预算裁剪。** 砍掉它等于整轮报废，模型输出无法解析。
2. **危机指令不参与预算裁剪。** 它是安全底线，优先级高于人格与剧情。
3. **角色卡不裁剪。** 超长直接报错（`MAX_CONTEXT_CHARS`），不静默截断——
   悄悄砍掉角色卡末尾的设定，比明确报错危险得多。

## 角色卡格式

最简六字段，必填只有两个：

| 字段 | 必填 | 说明 |
|---|---|---|
| `identity.name` | ✅ | 名字 |
| `description` | ✅ | 角色描述，上限 18000 字 |
| `personality` | | 性格 |
| `speech_style` | | 说话方式（保留字段，当前未注入） |
| `greeting` | | 开场白。新建会话时作为她的第一条消息落库 |
| `examples` | | 口吻示例，user/assistant 对。**决定口吻的最大因素** |
| `scenario` | | 角色自带情境（当前场景优先） |

`cards.py` 支持导入 SillyTavern 的 `chara_card_v2`，并会剥掉卡里自带的
`system_prompt`——防止用户导入的卡覆盖产品边界。

角色卡有两个来源目录，用户导入的优先级更高：

```
assets/character_<id>.json      内置
data/characters/<id>.json       用户导入（不进版本库）
```

## 场景卡格式

**编译器当前只读 `context` 字段**，其余字段是历史遗留，不生效：

```json
{
  "id": "cafe",
  "name": "街角咖啡店",
  "stage": "first_meet",
  "context": {
    "place": "午后的街角咖啡店",
    "situation": "你和用户坐在窗边聊天，各自点了饮品。你是来坐坐的，不默认扮演店员。",
    "details": ["窗外有人经过", "店里有轻音乐"],
    "opening": "初次进入时可自然说起眼前小事，跟随用户话题。"
  }
}
```

`situation` 是最重要的一句——它决定她在这个场景里是什么身份、什么状态。

场景卡**只能从 `assets/scenes/` 加载**，没有用户可写的目录，加新场景需要
手工放文件并重启。这是当前的能力缺口。

### 尚未接回编译器的字段

场景卡里还存在这些字段，编译器一次都不读，属于历史遗留：

| 字段 | 原本的作用 | 状态 |
|---|---|---|
| `movement_line` | 动线：用户不说话时她做下一件事 | 未接线 |
| `interaction_gate` | 什么时候必须开口 / 允许沉默 / 绝对不能说 | 未接线 |
| `scene_goal.progress_condition` | 剧情走完的可判定条件 | 未接线 |
| `topic_policy` | 话题白名单与开启规矩 | 未接线 |
| `pacing` | 这一场的说话节奏与段数 | 未接线 |

`scene_has_progressed()` 目前写死返回 `False`，场景推进机制处于停用状态。

**内容团队注意：改这些字段不会影响她的表现。** 要调整她在这个场景的表现，
改 `context.situation`。

## 关系状态

五个阶段，由亲密度数值推导（存数据库，不是写死在角色卡里）：

| 阶段 | 亲密度 | 场景 | 她的主动程度 |
|---|---|---|---|
| 初次相识 | 0–9 | 咖啡店 | 低，以回应为主 |
| 逐渐熟悉 | 10–19 | 河畔公园 | 中，会主动抛话题 |
| 相处自在 | 20–29 | 游乐园之夜 | 高，会拉着对方做决定 |
| 亲密陪伴 | 30–39 | 雨夜客厅 | 低，更愿意等对方先说 |
| 深度信任 | 40+ | 午夜之后 | 低，敢于直接表达 |

每个阶段还有一个**情绪强度上限**（0.5 → 1.0），防止刚认识就情绪爆发。

## 记忆四层

| 层 | 存什么 | 存多久 | 怎么用 |
|---|---|---|---|
| 工作记忆 | 当前对话原文 | 这通对话 | 最近 60 条进原生历史 |
| 短期摘要 | 最近几天的浓缩印象 | 滚动覆盖 | 常驻进上下文 |
| 长期记忆 | 永久事实与经历 | 永久 | 按相关度召回 5 条 |
| 未闭合话题 | 没结的事 | 有始有终 | 按时间提起，一次只提一件 |

分区维度只有一个：`character_id`。场景是记忆的标签，不是隔离墙。

召回打分 = 关键词重合 0.55 + 时间新鲜度 0.20 + 类型权重 + 场景加成 0.15 + 置信度 0.10。
低于 0.18 分宁可不召回——不相关的记忆混进上下文比没召回更糟。

**有一类记忆不参与打分**：称呼类高置信事实常驻注入。因为「你还记得我叫什么吗」
和「用户希望被称呼为「阿哲」」零字符重合，纯相似度召回必然失败，
而这类漏掉就是信任崩塌级别的事故，不能赌召回率。

置信度低于 0.5 的记忆直接拒收。错误记忆会自我强化，比漏记更糟。

## 校验器

模型每次输出的遵循度有方差，稳定性不能只押在提示词上。
规则能判断的绝不交给模型——免费、瞬时、100% 准。

| 规则 | 查什么 | 失败处理 |
|---|---|---|
| V1 | 有可朗读的台词（`brief`/`may_silent` 策略下豁免） | 硬失败，重生成 |
| V6 | 台词不残留 `@seg` / `[sep]` | 硬失败 |
| V10 | 不含禁用词 | 硬失败 |
| V7 | 段数在 1 到 6 | 软降级 |
| V9 | 单段 ≤100 字、整轮 ≤400 字 | 软降级 |
| V5 | 表情在场景白名单内 | 软降级 |
| V8 | 情绪强度不超过当前阶段上限 | 软降级 |
| — | 不用 emoji、台词不夹带括号 | 软降级 |
| A1 | 不出现填话句式 | 软降级 |
| A2 | 用户提问时不得整轮反问 | 软降级 |
| A3 | 不逐字复述用户刚说的话 | 软降级 |

风格漂移用风格指纹重合度做粗粒度度量。它只测「说话像不像这个人」的一个侧面，
不能替代人工评审，阈值需要用真实模型的输出校准。

## 存储

单文件 SQLite，**所有 SQL 收敛在 `memory.py` 内**，业务代码不写 SQL。
这是将来换 PostgreSQL 只改一处的先决条件。

| 表 | 存什么 |
|---|---|
| `conversation` | 会话：归属人、角色、场景、亲密度、记忆开关 |
| `message` | 对话原文，带 `spoken` / `seg_count` |
| `reply_record` | 每轮完整 payload（含旁白），支持重开页面还原 |
| `feedback` | 每轮的好评差评与备注 |
| `summary` | 滚动摘要 |
| `memory` | 长期事实，带置信度、来源场景、可见性 |
| `open_loop` | 未闭合话题 |

启动时 `_migrate()` 自动给旧库补新增的列。上线过的库不能重建，用户数据不能丢。

## 已知缺口

- 长期记忆的抽取是规则通道，只有姓名、工作、偏好、点单、事件这几类。LLM 抽取通道未接。
- 场景卡不能通过界面新建，只能手工放文件。
- 场景推进、动线、交互闸处于停用状态（见上文）。
- 记忆召回是关键词加规则，向量检索未接。
- `speech_style` 字段保留但未注入提示词。
