# 05 · 五段式提示词架构

## 五张卡各管什么

| 卡 | 回答的问题 | 文件 | 变更频率 |
|---|---|---|---|
| character_card | 她是谁 | `assets/character_elise.json` | 极低 |
| scene_card | 现在在什么处境里 | `assets/scenes/*.json` | 低 |
| relationship_state | 你们多熟 | 数据库 + `persona.STAGES` | 每轮 |
| style_anchor | 说得符合什么规格 | `persona.STYLE_ANCHOR` | 极低 |
| boundary_policy | 什么情况必须怎么办 | `persona.BOUNDARY_POLICY` | 低 |

**正交原则**：角色卡只写「她是谁」，场景卡只写「现在在什么处境里」。
两者不得互相引用，任意组合都要成立。做到这一点，N 个角色 + M 个场景只需要
N + M 份内容；做不到就是 N × M 份，是维护地狱。

校验器 `persona.validate_assets()` 会自动检查这条：角色卡里出现
「咖啡店」「吧台」「客人」这类场景绑定词就直接报错。

## 角色卡为什么要有 trait_causes

普通写法只给形容词：

```
核心矛盾：待人温柔、很会照顾别人，却不习惯向别人求助
```

模型只能猜怎么演。正确写法是「性格 → 成因 → 具体表达」三段：

```json
{
  "trait": "用「没关系」挡掉关心",
  "caused_by": ["小时候发现说出来也解决不了，反而让人担心"],
  "expression": "被问「你还好吗」时先说没事，停顿一下，才可能补一句真话。"
}
```

`expression` 是可执行的行为定义。模型照着演，不用猜。
校验器强制要求每条因果链都有 `expression`，缺了直接报错。

## 场景卡为什么要有动线

用户不说话时，她不该硬找话说。但她也不能凭空消失。
解法是 `movement_line`：把她在这一场会做的事排成有序的动作节点。

```json
{
  "id": "make",
  "action": "转身磨豆、压粉、萃取、打奶",
  "may_speak": "不说话。这一段用动作呈现"
}
```

配合 `interaction_gate`，判断她此刻该不该开口：

- `must_speak`：必须说话
- `may_stay_silent`：可以只给动作
- `never`：绝对不做的（不要为延续对话而提问、不要每次两个气泡……）

编译器据此算出本轮的 `speak_policy`，取值 `must` / `brief` / `may_silent` / `close`，
写进提示词，并交给 checker 校验。

## 场景走完要有可判定的条件

`scene_goal` 分三段：

```
primary              这一场要达成的体验（描述）
progress_condition   走完的判断条件（可判定）
on_progress          走完之后做什么
```

`progress_condition` 必须能本地判定，例如「用户说了收尾语」或「对话轮数达到 12 轮」。
编译器算出 `scene_progressed`，走完就把策略切成 `close`——不再开新话题。

只有描述没有条件，等于把「自检表当成既成事实」，剧情走完了她也不知道该往前。

## 段数不是固定两段

风格锚点里明确写死：

```
min_segments: 1
max_segments: 4
default_segments: 1
```

提示词里写「默认只发 1 段。只有当下确实同时有「要做的事」和「要说的话」时才拆成 2 段。
不要为了凑数而分段。」

checker 的 `V7_segment_count` 按这个范围校验。用户消息表新增 `seg_count` 列，
把每轮实际段数存下来，下一轮渲染进上下文时标成 `[只说了一句]` / `[发了 2 段]`，
让她能看见自己上一轮是不是话太多。

## 边界策略必须带触发条件

只渲染 `action` 会把语义搞反。`ai_disclosure` 的动作是「承认自己是 AI」，
如果被放进「绝对不做的事」标题下，模型读到的意思正好相反。

所以渲染时强制成对出现：

```
- 当[trigger]时：[action]
```

## 上下文注入顺序

```
[最高优先级] 危机指令（永不裁剪）
[固定]       角色卡内核 + 风格锚点 + 边界策略
[随阶段变]   关系状态
[随场景变]   场景卡 + 动线 + 交互闸
[不裁剪]     输出格式规则 + 本轮说话策略
[每轮变]     召回记忆 + 未闭合话题 + 最近对话
```

顺序决定成本：固定前缀放最前，才能吃到前缀缓存。

## 未解锁的线索不进上下文

`clue_ladder` 分三层：`public` / `explorable` / `deep`。

- `public` 写进固定前缀
- `explorable` 和 `deep` **物理上不注入**，即使被模型问到也不存在

不是「告诉模型别说」，是让模型不知道。约束比提示可靠。
